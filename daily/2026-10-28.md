`tools/gutenprint_ref/build_ref.sh` 的核心流程（已核验原文）：下载 `gutenprint-5.3.5.tar.xz` → `./configure --disable-nls --without-gimp2 --without-cups --disable-libgutenprintui2 ... --enable-static` → 编译 `src/main` 与 `src/xml` → `cc ... gp_ref.c ... libgutenprint.a` → 用 `STP_DATA_PATH=$GP/src/xml ./gp_ref 300x300dpi ref300.prn` 等生成参考流 → **再为 `canon_bjl.h` 的每个 stream 变体各建一个 Gutenprint 驱动**（`MG2900:bjc-MG2900-series`、`iP2800:bjc-iP2800-series`、`E3100:bjc-E3100-series`、`MP230:bjc-MULTIPASS-MP230`、`iP2700:bjc-PIXMA-iP2700`）。

> Decodes the Gutenprint stream into raw ink planes, re-encodes those planes with host/bjl_host (our C code), then compares the two streams command by command. **⭐⭐⭐⭐⭐⭐⭐⭐⭐ 「Gutenprint 在页高是 8 的倍数时会丢弃最后一个 raster block」这个缺陷被写进了**对照器的豁免说明** —— 这正是本日报连续记录多日的那条原则的又一样本：**当参照系自己有 bug 时，正确做法不是放宽判据，而是把偏差的方向、原因与量级写清楚，并让对照器只在这一处放宽。** **⭐⭐ 而更关键的是：这个偏差方向是**对自己有利**的（自己多出尾部空白块），如果对照器默默放过，就等于给了自己一个无法被发现的作弊空间。**

## 最值得关注的方向

1. **⭐⭐⭐⭐ 「把裁决权交给一个别人能独立重跑的东西」是本日最强的共同信号。** nyxis 交给 Lean 内核、CFSG 交给 Lean 内核 + 对照机制、esp32-usb-to-airprint 交给 Gutenprint 的字节流。**⭐ 而三者的边界声明完整度递减（nyxis 写全了红/黄两层与定理目录，CFSG 没有 `docs/`，esp32 有 19 行机型表但 18 行标黄）—— ⭐⭐ 边界声明的完整度与 star 数无关。**
2. **⭐⭐⭐⭐ 「假设可以被人改」是一个技术严谨系统里最容易漏掉的治理面。** nyxis 明写假设「由人裁量修改」，而本日唯一一条外部 issue（#33，日文供应链尽调）问的正是「谁有权批准什么」。**⭐ 技术证明的可信度上限，最终由「谁能改假设」决定。**
3. **⭐⭐⭐⭐ 「找到一处 `sorry` 不等于项目不诚实」是一条可立即迁移的方法论。** CFSG 的 `Comparator/Challenge.lean` 以 `:= sorry` 作为题面骨架，配 `comparator.json` 的 challenge/solution 双模块与 `permitted_axioms`；而两处 `meta def` 里的 `sorry` 只是一个默认关闭的调试开关。**⭐ 判断标准是「这处 sorry 在体系里扮演什么角色」，不是「有没有 sorry」。**
4. **⭐⭐⭐⭐ 「指纹会过期」这个问题的正解是「识别稳定特征」，而不是「勤更新快照」。** brotli-checker 的新 commit `Recognize stable Brotli decoder tables independently of patch fingerprints` 正是在做这件事，而它的 `fingerprints.json` 的 `verified_on` 至今仍是 2026-10-23。**⭐ 快照仍会过期，但判定不再完全依赖它。**
5. **⭐⭐⭐ 「标识符要用稳定量，不要用易变量。」** KohakUnlock 的一次真机失败（`diskpart` 在 C: 收缩后把 payload 从 part 5 重编号为 part 4）换来了「payload 只按 GUID 绑定」的修复与一个回归测试 `APP_PAYLOAD_RENUM`。**⭐ 这与「不要把会变的东西当锚点」是一条通用工程纪律。**
6. **⭐⭐⭐ 「公开未验证范围」已经是跨领域的默认实践，而不是某个项目的美德。** 今日 5 个新项目 + 3 个跟踪项各自公开了未验证范围：COGBox 的「RTX 3080 Ti + 脚本化跑章节」、esp32 的 18/19 行机型标黄、anymove 的 spider walk 0.36–0.49 fails、raven 的软件 Vulkan、nyxis 的红/黄两层、CFSG 的无 `docs/`。**⭐ 这可能比今日任何一个具体项目都更值得记。**
7. **⭐⭐⭐ 判据仍然是 subs / oi / commits / pushed_at，而不是 star —— 今日三对反例齐了。** `ub-mode` +517% 而 commits 0（但 subs 1→16）、`xss-audit` +28% 而 commits 0、`mcreplay` ±0% 而 commits 0 且 subs 0；对照 `android-ad-cleaner` +335% 而 oi 22→178 / releases 2→7 / commits +32、`ex-ussr` +98% 而 releases 2→7 / contributors 4→14 / commits 41→152。**⭐⭐ 而「blob SHA 相同」是本日报今日新增的最强单项判据（6 个仓库共享同一个 `.gitignore` SHA）。**
8. **⭐⭐ 「订阅」可能是一种被低估的关注形式。** `ub-mode` 的代码一个字节没动、仍无 LICENSE，但 `subscribers_count` 从 1 涨到 16。**⭐ 对原则型/指针型仓库，订阅数比 star 更接近真实意图。**
9. **⭐⭐ 「文档与实现之间的张力」必须被记下来，而不是被抹平。** KohakUnlock 新增 `KOH_AUTOCONFIRM_MS` 自动尝试，而 `docs/SAFETY.md`（SHA `b8b58526…`，2,917 字节）里的「Do not automatically retry an uncertain hardware mutation」原样保留。**⭐ 本日报不替它下结论，标为待作者澄清 —— 这正是「边界写进可核验位置」的必要代价：一旦写下来，它就会与后来的实现对账。**
