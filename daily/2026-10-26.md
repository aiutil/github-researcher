## 今日重点趋势（按排名）

### 趋势 1：同一个 CVE 上，两条方向相反的检测路线——主动探测与离线盘点，都把「不确定」设计成独立的输出状态（趋势分 91）

本日最重要的观察不是「又多了几个 PoC」，而是**两个由安全厂商自己写的检测工具，在同一 CVE 上选择了互斥的路线，而它们各自都拒绝把「测不出来」说成「安全」**。

**⭐ `assetnote/node2shell-scanner`（18.5 小时 48⭐ ⑂6，fork/star 12.5%，subs 1，oi 0，Python，MIT，11 KB，Organization `assetnote`（创建于 2018-01-09，40 个公开仓库，995 followers），**仅 1 个 commit**，contributors API 返回 1 人，`releases` API 返回 0 个）**

它是**主动式**的：README 明写「The scanner sends four one-byte controls to learn how the endpoint handles valid Brotli JSON, malformed Brotli, requests without a JSON content type, and unsupported encodings. It then streams a 23,068,764-byte Brotli probe and repeats the valid control.」

**⭐ 而它的判定条件是三条同时成立，而不是「探测成功 = 漏洞」：**

> A target is reported vulnerable only when **the full probe reaches the valid route-response class**, **the malformed-response class is distinct**, and **the final control confirms the endpoint remained stable**. This matches Assetnote's internal postmodule detection logic and **does not execute a command**.

这三个条件对应三个可被证伪的断言：**① 探针真的被解码到路由（而非被中间层吞掉）；② 畸形输入的响应与之相异（而非两者都返回同一个 200 空体）；③ 端点没有因探针而崩掉（排除「打崩了所以看起来不一样」）。**

**⭐⭐ 代码层面这些约束是硬编码的、可逐行核验的**：`scanner.py` 共 1,163 行，其中 `PROBE_BYTES = 23_068_764`、`PROBE_REPETITIONS = (1 << 21) - 1`、`PROBE_PREFIX` / `PROBE_UNIT`（`f5a8473dea518f7ad4a31e`）/ `PROBE_SUFFIX` 三段拼接，并有一条**自校验断言**保证拼接长度恰好等于 `PROBE_BYTES`；四个对照请求在 `request_evidence()` 里被固定登记为 `"ff (Content-Encoding: br; no Content-Type)"` / `"3b (Content-Encoding: br; Content-Type: application/json)"` / `"ff (Content-Encoding: br; Content-Type: application/json)"` / `"x (Content-Encoding: x; Content-Type: application/json)"`；比较函数 `same_exact()` 要求双方 `error is None`、**未截断**、状态码相同、content-type 相同、**body 逐字节相同**（另有仅比状态码的 `status` 模式）；`scan_url()` 在多路径场景下**只要有一个路径判为 vulnerable 就立即返回 true**，否则回退到第一个「非 inconclusive」的结论。

**⭐⭐⭐ 而它对「测不出来」的处理是本日报最值得抄的一处：**

| 输出态 | 触发条件 | 证据 |
|---|---|---|
| `vulnerable: true` | 三条判定同时成立 | 完整请求/响应证据（含被脱敏的敏感头） |
| `vulnerable: false` | 探针未到达有效路由且响应类相异 | 同上 |
| `vulnerable: null` / `verdict: INCONCLUSIVE` | 网络错误、超时、无响应等 | `result["error"]` 记原因 |

**退出码是 `raise SystemExit(1 if vulnerable_count else 0)`——即「没有发现漏洞」以 0 退出。** **⭐ 这个设计与本日报记录的 mcreplay 的 0/1/2/3 退出码、brotli-checker 的 0/1/2/3 退出码属于同一族：把「判定结果」编码成 CI 可断言的离散状态，而不是一句警告。**

**⭐⭐⭐⭐ 而它对自己造成的网络影响是写进 README 的可复算数字，不是免责套话：**

> Each tested endpoint receives **five one-byte requests and one 23,068,764-byte probe**. The probe uses `Expect: 100-continue`, so a proxy can reject its advertised size before the body is uploaded.

**⭐ `Expect: 100-continue` 这一行是真正的工程细节**——它让代理可以在上传 23 MB body **之前**就按 `Content-Length` 拒绝该请求，因此这个「23 MB 探针」在有代理的环境里可能根本不会上传。**这是把「检测器的副作用」主动交还给部署方的网络层去裁决。**

## 最值得关注的方向

1. **⭐⭐⭐ 「判定结果」正在从文本变成退出码。** 本日三个独立项目——scanner（`Vulnerable`/`Not vulnerable`/`INCONCLUSIVE` + 退出码 1/0）、brotli-checker（0/1/2/3 且明写 exit 0 ≠ 应用安全）、mcreplay（0/1/2/3，10-25 已记录）——都在把结论编码成 CI 可断言的离散状态。**⭐ 三者都拒绝把「没测出问题」表达成「安全」。**
2. **⭐⭐⭐ 「独立性」与「来源」必须被结构化，才能防止「看起来很充分」的伪证。** ex-ussr 的 `independence_group` + 六个离散证据状态 + 代码级强制校验，是本日报见过最完整的「防伪证」结构。**⭐ 这条与本日报此前记录的「证据分级」（mcreplay 的 `S:`/`O:`）属于同一族的两个不同实现。**
3. **⭐⭐⭐ 原则文档正在被「绑定到能真的拒绝你的工具」取代。** ub-mode 把 CRAP<10 / 重复度<0.8 / 变异测试绑到三个独立的、真实存在的、有 star 的工具仓库上。**⭐ 而它自己只有 4 KB —— 这是分工，不是不够。**
4. **⭐⭐ 硬件/特权实验的正确形态是「默认关闭 + 失败模型写成不可协商顺序 + 接受可能永久损坏」。** KohakUnlock 的 `handoff_safe` 门、「SSH 无法救回网络起来之前停住的机器」、「不要自动重试一次不确定的硬件变更」，是本日报见过最硬的失败模型。
5. **⭐⭐ 「同一个前提上的第三个修复」应该先被写成一句话。** ub-mode 的 `Attack the Premise`：「write that premise in one sentence and count which actors hold the imbalance. Remove the assignment. Do not start another fix until you have done that.」
6. **⭐⭐ 混合许可项目的正确形态是机器可读的组件清单 + 明写「历史授权仍有效」。** raven 的 `LICENSES.json` 一次性解决了本日报记录多日的两类许可元数据问题。
7. **⭐⭐⭐ 事件驱动的注意力洪峰会同时带来真工具与同构农场。** 本日 CVE-2026-111497 潮里同时出现了两个厂商级检测工具与 17 个 2 文件的同构仓库 —— **必须用结构层证据（体积、文件数、账号名、star/fork 取值集合）而非热度来区分。**
8. **⭐⭐ 「昨日的档案今天可能全部作废」必须被当成常态来设计流程。** raven 一天内换了语言、换了许可、换了目录结构。**⭐ 因此「最近动态」与「作废声明」是档案的必要组成，不是可选装饰。**

## 风险与机遇

### 机会

1. **⭐⭐⭐⭐ 立刻可用且证据完整的两件：brotli-checker（MIT，3 个 release，纯标准库的独立扫描器 + `uv` 做源码发现）与 scanner（MIT，仅 `h11` + `tqdm` 两个依赖）。** **⭐ 二者都在各自 README 的第一屏就写清了边界，而边界之内是可用的。**
2. **⭐⭐⭐ 一个「五个口径的迁移检查器」可以直接抄进任何有依赖清单的项目。** brotli-checker 的四档退出码 + 「exit 0 does not establish that the running app is fixed」+ 「A fixed copy does not clear another」，几乎可以逐字移植到任何「升级依赖」场景。
3. **⭐⭐⭐ `independence_group` 机制可以原样套用到任何「多来源交叉验证」的场景**（安全事件关联、供应链溯源、论文引用、情报分析）——**⭐ 它的通用形式是「同一原始来源的多份拷贝必须共享一个分组标识，且分组不能凭空声明」。**
4. **⭐⭐⭐ 「CVSS 9.2 的 PoC 仓库」与「厂商的检测工具」在同一 CVE 上并存，本身是一个信号**：漏洞的注意力会同时吸引研究者与防守方，**而防守方工具的可核验性明显更高**（有退出码、有版本表、有指纹来源、有 `--json` 证据输出）。
5. **⭐⭐ 「不要自动重试一次不确定的变更」是一条可以立刻写进任何自动化流程的规则。**
6. **⭐⭐ `Attack the Premise` 规则可以立刻写进任何 agent 的提示词，不需要任何工具配合。**
7. **⭐⭐ raven 的 `LICENSES.json` 结构可以成为本仓库自身许可档案的模板。**
8. **⭐⭐ `evals/*.yaml` 里把「不该做什么」写成带 `expected` 的用例，是任何 skill 类项目都该有的东西** —— **⭐ 本日 ex-ussr 的 `should_not_trigger` 与 `captcha` 用例，比 100 条成功案例更能说明设计意图。**
