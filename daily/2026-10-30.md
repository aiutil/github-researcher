### 趋势 3：与农场同框的三个真项目，都把「结论交给可复算的东西」（趋势分 91）

**⭐⭐⭐ 本日最值得记的方法论观察是：在这份 100 个仓库的取样里，农场与真项目混在同一份 star 榜单里，而**区分它们的不是 star，是「它是否把自己的结论交给一个别人能独立重跑的东西来裁决」。**

#### ⭐⭐ `interplains/Zero-Breach-Toolkit`（3,543⭐ ⑂381 · **subs 33** · 55 commits · **14 个 release** · Apache-2.0 · 1,113 KB）

**⭐⭐⭐⭐ 它最硬的一处，是把「我的扫描器干净」与「你安全」这两件事**明确切开**—— 而且是用三个并列的句子切开的：**

> - **Read-only.** It does not modify source evidence or system settings. It writes only temporary database snapshots and the reports you ask for.
> - **No network requests during a scan.** It never looks up spyware addresses and has no upload feature. Python network calls are blocked and redirected paths are refused. **This is not an operating-system network sandbox**; see [PRIVACY.md](PRIVACY.md).
> - **States its limits.** Every report says what was found, how strong the evidence is, and what could not be checked. **A clean result is never presented as proof that you are safe.**

**⭐⭐⭐⭐⭐ 而 `PRIVACY.md` 里那句自我设限是本日报今日见过最诚实的一处技术声明：**

> **These guards are not an operating-system network sandbox: POSIX network mounts and concurrent filesystem changes remain limitations. Use operating-system network isolation when strict offline execution is required.**

**⭐⭐⭐⭐⭐⭐ 即：它明说「我的『无网络』保证有已知的逃逸口，请用操作系统级隔离来补」。** **⭐⭐⭐⭐ 这与本日报 10-28 记录的 nyxis「a passing integration test is never a substitute for a formal proof」是同一条纪律的两种形态 —— **两者都在说「我的保证有边界，边界我写下来了」。**

**⭐⭐⭐⭐⭐⭐⭐⭐ 而它的验证路径是本日报今日最值得抄的一份文档 —— `docs/VERIFYING.md` 给出**两条互相独立的验证**，并明确要求「Use both」：**

**① 签名验证**（对照一个你已经信任的密钥）：
```
gpg --show-keys --with-fingerprint archivegenocide-signing-key.asc
gpg --import archivegenocide-signing-key.asc
gpg --verify SHA256SUMS.txt.asc SHA256SUMS.txt
sha256sum -c SHA256SUMS.txt
```
完整指纹写死为 `C24E C92B 12D6 670A 2516 065F 9B4D 5754 99AF A53C`，并附「compare that fingerprint with [ArchiveGenocide's verification page] or another record you already trust」，还明写「**Never ignore a fingerprint mismatch or a failed verification.**」。

**② 自行复现构建**（不依赖发布者）：
```
git checkout v0.1.13
python build/bundle.py
sha256sum dist/zero-breach-toolkit.py
```
原文：「**The build is deterministic, so a mismatch means something is wrong, not merely different.**」以及「Running from source is the other half of the same idea: **nothing is compiled, and every line the tool executes can be read in the clone.**」

**⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐ 而这份文档里最反直觉、也最值得单独抄走的一段，是「为什么没有代码签名」：**

> **Why there is no code signature**
> There is no signed Windows release, and none is planned while the project stays anonymous. Code-signing certificates require a verifiable legal identity, and every signing route, including [SignPath Foundation](https://signpath.org/), expects named, publicly identified maintainers and approvers. **This project does not have them, by choice. It claims no certificate, signing service or signed binary, and asks nobody to trust a downloaded signature.**

**⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐⭐ 即：它没有签名二进制，于是它给的是**另一条路**（可复现构建 + 分离签名 + 指纹对照 + 「从源码运行时没有编译，每一行都能在 clone 里读」），并且**明确说明「我们没有代码签名」这个缺口，而不是留白或假装有。** **⭐⭐ 本日报认为这是本日报见过最完整的一次「在受限条件下仍把验证路径做到可复算」的处理。**
