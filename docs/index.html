本日最硬的方法论发现是**给判据加上对照组之后，11-12~11-15 建立的「账号注册聚集度」判据被证伪了** —— ⭐⭐⭐⭐⭐ 实测 15 个 Trending 仓库各 100 个 fork（1,500 个 fork owner 账号）中「7 天内新建账号」占 **38.0%**，⭐⭐⭐⭐⭐ **而对照组 11 个仓库的 1,100 个 fork owner 中该比例是 40.5% —— 更高**；⭐⭐⭐⭐⭐ **逐仓库看更反直觉：`golang/go` 是 80/100、`rust-lang/rust` 是 72/100、`torvalds/linux` 是 71/100、`sveltejs/svelte` 是 88/100，⭐⭐⭐⭐⭐ 即「短期账号集中 fork 热门仓库」是 GitHub 的常态行为而非攻击特征**；⭐⭐⭐⭐⭐ 与之并列的第二个发现是**「版本发布」这条判据必须从一维拆成四维（tag 数 / release 数 / tag→commit→源码 diff 是否闭合 / 资产是否随版本演进），⭐⭐⭐⭐⭐ 本日实测四个真项目给出四种形态** —— ⭐⭐⭐⭐⭐ `alibaba/open-code-review` 100 release × 7 asset（366 MB，含 sha256sum.txt，**下载 57–951 次**）· `getarcaneapp/arcane` 100 release × 41 asset（1.78 GB，**无 SBOM**）· `backnotprop/plannotator` 100 release × 36 asset（**含 CycloneDX SBOM**，但下载仅 1–12 次）· ⭐⭐⭐⭐⭐ `GoogleChrome/modern-web-guidance-src` **100 个 tag 但只有 1 个 release**（且是 prerelease 的审计数据 JSON），⭐⭐⭐⭐⭐ **而这 100 个 tag 的 commit 全部真实改动了 RAG 索引产物（`guide-chunk-cache.i8/.json/.scale.f32`），其父 commit 10/10 触及源码** —— ⭐⭐⭐⭐⭐ 即 11-16 记录的「假版本号」（`steam-library-bridge`）、11-17 记录的「多而实」（`ffmpeg-skill`）与本日新增的「有 tag 无 release」是**三种不同状态**，⭐⭐⭐⭐⭐ 而判据恰恰在于「链上有没有真实 diff」而非「功能 commit 在前还是在后」⭐⭐⭐⭐⭐ （本日 `open-code-review` 与 `plannotator` 各自实测到功能 commit 在 tag 与在父上交替出现）；⭐⭐⭐⭐⭐ 第三个发现是**「SKILL.md 数量」是一个被复制放大的计数，必须拆成三个独立指标**：⭐⭐⭐⭐⭐ 实测 12 个 skill 类 Trending 项目，`affaan-m/ECC` 的 **1,087 个 SKILL.md 只对应 330 `cursor/plugins` 173 / 113（1.53×），⭐⭐⭐⭐⭐ **而 `Claude-BugHunter`（83/83）、`superpowers`（15/15）、`addyosmani/agent-skills`（25/25）、`anthropics/skills`（20/20）、`stitch-skills`（16/16）是零复制**；⭐⭐⭐⭐⭐ **关键的反例是
