unclebob/ub-mode

一句话定位

一份把软件工程原则绑定到四个能真的拒绝你的工具上的 agent skill——它自己只有 4 KB、2 个文件、4 个 commit，而真正的门禁能力在 crapper / dryer / mutator / uml-viewer 四个独立仓库里。

它解决的问题

AI 编码 agent 的失效模式不是「不会写代码」，而是「写出一堆看起来合理、但实际上什么都没验证的代码」。

具体表现：一个函数返回 None，测试仍然通过；两段逻辑重复的代码被复制粘贴；圈复杂度 47 的函数里藏着三个早退分支；变异测试显示你的断言根本不区分实现变更。

⭐ 而「写一份 AGENTS.md 说要有测试」显然不管用——因为规则没有强制力。 这个项目的核心主张就是：原则必须绑定到一个能真的拒绝你的工具上。

为什么值得关注（2026-10-26）

⭐⭐⭐ 因为它是本日唯一一个「原则文档 + 可执行门禁」成对出现的样本，而且门禁是真实的、独立的、有 star 数的公开仓库。

可核验的硬事实：

  1. ⭐⭐⭐ 四条原则各自绑定到一个独立的、真实存在的工具仓库（README 的表格原样列出）：
工具 仓库 star / fork 语言 / 许可 判据
crapper unclebob/crapper 109⭐ ⑂14 Python / 0BSD 圈复杂度 + 覆盖率 → CRAP < 10
dryer unclebob/dryer 43⭐ ⑂9 Python / 0BSD 结构重复度 → ≥ 0.8 即消除
mutator unclebob/mutator 58⭐ ⑂8 Python / 0BSD 变异测试：覆盖未覆盖、杀死存活变异体、删除死代码
uml-viewer unclebob/uml-viewer 449⭐ ⑂51 Clojure / spdx null 可视化组件、覆盖率、CRAP、变异分数与依赖方向
  1. ⭐⭐⭐ README 明确说它「relies on deterministic quality-gate tools to enforce structure, complexity, duplication, and test thoroughness」——即它自己不做判定，它把判定外包出去。
  2. ⭐⭐⭐ SKILL.md 里最锋利的一条判据是可执行的：「Test Behavior, Not Implementation —— The test calls the code the way its user does and checks the result that user would see. If the test would still pass when every function returned nothing, throw it out.」
  3. ⭐⭐⭐ 而本日报认为最有迁移价值的是 Attack the Premise 这一条：「When two fixes that share one premise fail the same gate, write that premise in one sentence and count which actors hold the imbalance. Remove the assignment. Do not start another fix until you have done that.」
  4. ⭐⭐⭐ 而它的作者身份与它的仓库体量形成鲜明对照：unclebob 账号创建于 2008-11-27，106 个公开仓库，17,434 followers。

热度来源判断

⭐⭐⭐ 热度主要来自作者身份，而仓库体量说明它是一个「指针」而非「实现」——必须把这两件事分开记录。

  • ⭐⭐⭐ 最可核验的解释是作者的关注度：unclebob（Robert C. Martin / Uncle Bob）有 17,434 followers、106 个公开仓库、18 年账号历史。341⭐ 在 6.5 小时内获得，与 17k followers 的规模是相称的。 这是身份驱动的注意力，而非工具被大规模采用的证据。
  • ⭐⭐ 硬证据反证「采用」：subscribers_count = 1、open issues = 1、contributors API 返回 1 人、releases API 返回 0 个、topics 为空数组、仓库仅 4 KB / 2 个文件 / 4 个 commit。⭐ 即 341⭐ 的背后几乎没有人在「订阅」或「使用」它。
  • ⭐⭐⭐ 而这与它的四个伴随工具形成对比：crapper 109⭐ ⑂14、dryer 43⭐ ⑂9、mutator 58⭐ ⑂8 —— 这三个才是真正承载能力的仓库，而它们的 star 数全部低于 ub-mode。 ⭐⭐ 这说明本项目自己也知道「分发指针」不需要大工程量——4 KB 是设计选择，不是缺陷。
  • ⭐⭐⭐⭐ 而 fork/star 4.7%（16/332）是本日一批新项目里最低的一档（对比 ZiChuanLan/agent-purge 的 128.6%）。 ⭐ 这与「用户 fork 去改写一份 skill 文本」的典型模式不同——它更像是一个「被读、被抄、被引用」的对象，而不是一个「被分叉改造」的对象。
  • ⭐ 而它主动声明了来源：「loosely based on portions of @poteto's rules (poteto-mode / pstack), reduced」。⭐ 即它不是凭空原创，而是他人规则集的删减版——这是本日报见到的少见的、主动的归属声明。

关键技术亮点

  1. ⭐⭐⭐ 三段式结构：先能跑，再正确，再练习 SKILL.md（3,958 字节）的结构非常清晰：
  2. First Make it Work：Laziness Protocol / Foundational Thinking / TDD / Redesign From First Principles / Attack the Premise / Subtract Before You Add / Outcome-Oriented Execution / Build the Lever / Architecture
  3. Then Make it Right：Fix Root Causes / Sequence work into verifiable units / Test Behavior Not Implementation / Crapper / Dryer / Mutator / Refactoring
  4. Practice：Keep a Log / Guard the Context Window / Worktree Cleanup / Commit and Push

⭐ 而这个顺序本身就是一条主张：先让它跑起来，再让它正确——而不是一开始就追求正确。

  1. ⭐⭐⭐ 判据是数字，不是形容词
  2. CRAP < 10（crapper）：圈复杂度与覆盖率的组合指标
  3. duplication < 0.8（dryer）：结构重复度阈值

  4. 变异测试（mutator）：「cover the uncovered, kill the survivors, delete dead code」 ⭐ 三条全部可由工具机械判定——这是「原则」与「门禁」之间的桥。

  5. ⭐⭐⭐ 「假测试」的可操作判据

    If the test would still pass when every function returned nothing, throw it out.

⭐⭐ 这条判据的价值在于它可以被执行：把被测代码全部改成返回 None，跑测试，如果还绿 → 这个测试是假的。⭐ 这是一个可以机械化的证伪方法，而不是一条需要人来遵守的纪律。

  1. ⭐⭐⭐ Attack the Premise —— 本日报认为最具迁移价值的一条

    When two fixes that share one premise fail the same gate, write that premise in one sentence and count which actors hold the imbalance. Remove the assignment. Do not start another fix until you have done that.

⭐⭐⭐ 三个动词构成了完整的流程：write（把前提写成一句话）→ count（统计谁持有这个不平衡）→ remove（移除这个分配）→ and only then（在此之前不要开始第三个修复）。 ⭐⭐⭐ 而它命中的是一个非常具体的现实：今天有 17 个仓库共享同一个结构模板、3 个仓库共享同一个 CVE、2 个 Android 项目共享同一个「设备操作纪律」——当多个修复共享同一个前提而都卡在同一个检查上时，正确的动作是先识别前提，而不是开始第三个修复。**

  1. ⭐⭐ Subtract Before You Add 与 Fix Root Causes 这两条与 Attack the Premise 同族：它们都指向「先减少」而非「先增加」——这与本日报记录的 brotli-checker「不发送畸形流」和 KohakUnlock「默认禁用执行」是同一条工程直觉的不同表述。

  2. ⭐⭐ Guard the Context Window 这是一条针对 AI agent 特有的实践：上下文窗口是稀缺资源，需要主动管理。⭐ 这印证了本日报的推断——这些规则集是写给 AI 编码 agent 用的。

  3. ⭐⭐ 它把四个工具的调用也写进了流程 README 与 SKILL.md 提到 crapper / dryer / mutator 三个工具，并有 uml-viewer 用于可视化。⭐ 本日报未核验 SKILL.md 是否真的在流程里调用它们（而非仅列出名字）——这是本档案最关键的待观察项。

  4. ⭐⭐ 4 个 commit 的完整轨迹可核验 16:04:08 初始提交 → 16:05:10 文档 → 16:07:11 标注来源（poteto）→ 16:07:58 移除 Clojure 引用。⭐ 即最后一个 commit 是删掉了一个引用（uml-viewer 是 Clojure），而 uml-viewer 仍然留在 README 的工具表里——这暗示作者有意不把 Clojure 作为前置依赖。

架构启发

⭐⭐⭐ 核心启发：原则的可执行性不取决于它写得多具体，而取决于是否存在一个能拒绝你的工具。

绝大多数 AI 编码规范（「请写单元测试」「避免深层嵌套」「使用有意义的命名」）之所以无效，不是因为写得不清楚，而是因为没有任何东西会因为违反它而失败。ub-mode 的做法是把每一条原则翻译成一个阈值或一个工具调用：CRAP < 10、重复度 < 0.8、变异测试杀死存活变异体。⭐ 一旦判据是数字，违反就必然产生一个非零退出码——这才是「门禁」。

⭐⭐⭐ 第二个启发（本日报认为今日最具迁移价值的一条）：在开始第三个修复之前，先把共享的前提写成一句话。

Attack the Premise 的三步——write it in one sentence / count which actors hold the imbalance / remove the assignment——本质上是一句「别再打补丁了，先看看这个 bug 到底属于谁」。 ⭐⭐ 而它恰好命中本日被反复观察到的一个现象：今天有 17 个仓库共享同一个结构模板、3 个仓库共享同一个 CVE 触发条件、2 个 Android 项目共享同一套「设备操作纪律」。 在这种情况下，「第三个修复」几乎总是错的——真正需要做的是移除那个共同前提本身。 ⭐⭐⭐ 而这条规则的价值在于：它不依赖任何工具、不依赖任何语言、不依赖任何框架。 一个纯文本的 agent 提示词就能承载它，而它解决的问题是本日最普遍的那一类。

⭐⭐ 第三个启发：「先能跑，再正确」是一个真实的工程策略，不是懈怠。 三段顺序（First Make it Work → Then Make it Right → Practice）意味着它承认在第一阶段放弃质量是可接受的代价——这与本日报记录的 subtract before you add、Fix Root Causes 属于同一条思路：先让系统有可用的形状，再收敛质量。

⭐⭐⭐ 第三个关于「可证伪性」的启发：它给出的假测试判据（「把每个函数都改成返回 None，测试还通过就扔掉」）是本日报见过最干净的可证伪设计——因为它把一个主观判断（「这个测试有用吗」）转换成了一个二值实验。 ⭐⭐ 值得与本日报记录的 oss-verify oft check 对照：那个工具在 Print Assumptions 阶段拒绝越界公理，同样是把「我凭什么相信这个结论」变成一次显式的检查。

⭐⭐ 第四个启发：2 个文件、4 KB、4 个 commit 的体量，对这个项目是优点而不是缺点。 ⭐ 它把「维护面」压到了最小——一份文档不需要版本策略、不需要兼容矩阵、不需要测试。 ⭐⭐ 但同时必须记录它的反面：这个体量也意味着它对四个外部工具没有任何版本约束，而它自己不 vendoring——这是本档案标记的最大风险。

定位判断

分发指针（Distribution pointer），不是实现，也不是扫描器。

在 AI 编码工具的生态里，它属于「规则集」这一类。⭐⭐ 但它的独特之处在于：绝大多数规则集止步于文本，而它把文本翻译成了四个可执行的门禁。

⭐ 从架构位置看，它是一层「薄壳 + 厚外部依赖」：本仓库几乎没有代码，价值全部在四个独立的 Python/Clojure 工具里。⭐⭐ 这意味着评估这个项目的正确方式是评估那四个工具，而不是评估这 4 KB。

⭐⭐⭐ 而它与 DenisSergeevitch/ex-ussr-kinship-research 形成一组有意思的同日对照： 两个都是 agent skill，但一个把「证据强度」编码进代码强制（audit_evidence.py），另一个把「代码质量」编码进外部工具阈值。 ⭐⭐ 即：本日两个被验证过的 agent skill，都走了「把原则变成可机器判定的东西」这条路——只是一个自己写判定器，一个引用外部判定器。
