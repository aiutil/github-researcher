重点项目深度分析（top 3）

Deep Dive 1：OpenMOSS/MOSS-Image（5B base DiT + 强文本 + 布局 + 异构 GPU + ComfyUI + skill）

项目定位。 MOSS-Image 是 OpenMOSS 团队 2026-10-16 发布的 5B 参数 base DiT，双权重（Bib + SFT）+ ComfyUI 插件 + GPT-6 family agent skill 一体化交付。Apache-2.0 + Hugging Face + ModelScope + 简体中文 + 中文 Discord + Feishu Builders + QQ 群——基础盘完全对标国际开源社区 + 中文本地化。

技术亮点。 - 强文本渲染：SD / Flux 在长文本清晰度上一直不强，MOSS-Image 把这一痛点正面打，是中文场景下识字率上最大的开源 base - 布局控制：像素坐标 → 整数居中坐标 JSON 编译进 prompt，决定了设计的可重复性 - 4K 长 prompt：4K tokens，对长 prompt agent 工作流是关键 - 5B 紧凑高效：相对 Flux / SDXL 显著小，便于本地 + LoRA 微调 - 异构 GPU 训练：在"非英伟达"平台训练，对国产 NPU 友好 - ComfyUI 原生插件：通过 ComfyUI Manager 直接安装，向官方仓库合入中——意味着用户可以无缝接入 ComfyUI 工作流 - MOSS-Image Prompt Enhancer skill：给 GPT-6 family agent 提供"图像 idea → caption + Layout JSON"的本地 Python 工具脚本，不调用文生图服务，避免循环调用

风险。 - 训练数据 / GPU 集群与 SFT 配比未在 README 主页详述（需查 technical report） - GPT-6 family 是面向未来的 agent，当下主流 Claude / GPT-5.6 / Gemini 2.5 agent 是否能调用未明示 - 与 Flux / SDXL 同台竞技的画质上限未在 README 中量化 - 5B 紧凑 vs 异构 GPU 训练的合规性（如国产 NPU 部署的 license 边界）待核验

是否值得跟踪。 值得——这是 2026-Q4 国产生态首份严肃工程化 base DiT，agent-friendly + ComfyUI-friendly + 5B 紧凑 + 异构 GPU，与 Hugging Face、ModelScope、Feishu 等基础设施耦合深，长期看是生产可用候选。

Deep Dive 2：Noniv/web-ocean（WebGPU + 6-cascade FFT + CDLOD + LEAN + Hillaire + AgX + Claude Opus 5.5 写）

项目定位。 web-ocean 是 Noniv 个人 + Claude Code (Opus 5.5) 用 WebGPU from scratch + no engine 写就的实时海面渲染器：102 KB ocean.html + 61 KB ocean.min.html + npm + esbuild。MIT + 444⭐ ⑂82 fork/star 18.5%——fork 强烈（大量二次开发者要拆 wheels）。是 2026-10 上半月"Lone developer + Claude Code Opus 5.5 完整奉上一份细分领域引擎级实现"的稳定副线的延续（与 framemck/holloway、snuri00/ps2-web-recomp、LoreanXavier/pt-pc 一致）。

技术亮点。 - 6 cascades radix-2 FFT compute shaders：波长从 1103 m → 0.26 m（最长波长 vs 最短波长），workgroup memory 内完成 - CDLOD 17-level quadtree：6.25 cm 间距近端、160 km 视野，连续 LOD 形变（vertex morphing between levels） - Mip-mapped slope LEAN mapping：远海无 aliasing + 近端 specular 清晰 - Anisotropic Gaussian slope distribution with Smith masking：sun glitter 真 - Two camera-centred world-space foam maps（128 m + 1 km）：foam 衰减 + 顺风漂移 + age-related streak + procedural bubble texture - Hillaire 大气：transmittance + multiple-scattering + sky-view LUT + aerosol haze - 双云层：cumulus + fibrous altostratus，self-shadowing toward the sun + lit rims + silver linings + direction-dependent multiple scattering - HDR + 4× MSAA + 8-level bloom + AgX tone mapping：post pipeline 完整 - 6-8ms @ 2560×1440 RTX 5070 Ti：性能门槛极高，说明资源池化做得彻底

风险。 - 无 WebGL 回退：老浏览器 / iOS Safari 受限（README 明示"force Chrome onto the dedicated GPU"） - 远水偏深色 + 无海岸 + 无物体 + 仅 sunset 调好：README「Known limitations」明示三个 - CLAUDE 写就：意味着将来维护者可能"读不懂模型写过的代码"，是 AI-generated code 的典型脆弱性 - fork/star 18.5%：fork 显著高于 star，可能是大量二次开发需求与"AI 写就"绑定

是否值得跟踪。 值得——这是 2026-Q4 一份少有的"个人 + Claude Opus 5.5 完整奉上一份细分领域引擎级实现"的严肃工程化样本。fork 18.5% 暗示这会成为 WebGPU 引擎级实现的重要 reference 仓库。

Deep Dive 3：reason-machines/reason-network（P2P + iroh + Reason CLI + MCP + multi-harness mid-session push + tincan 升级）

项目定位。 reason-network 是 reason-machines 团队 2026-10-16 发布的 P2P team coding agents 总线：daemon 装到每台机器 + 队友机器直连 + iroh（n0）+ 跨 internet relay（可自建）+ MCP server reason-network + list_team / send_message / check_inbox + 8 个 harness（Claude Code / Codex / Cursor / Gemini CLI / Copilot CLI / opencode / pi / Reason）+ mid-session push + notify 弹窗 + menu bar icon + 由 tincan 升级而来。

技术亮点。 - P2P first：每机一个 daemon，iroh end-to-end，没有中央 server——只有当 peer 直连失败才走 n0（或自建 relay） - iroh（n0）作为 transport：end-to-end 加密 + 默认 n0 relay + 自建 relay 完全可能 - MCP server reason-network：Claude Code / Codex / Cursor / Gemini CLI / Copilot CLI / opencode / pi / Reason 八大 harness 一致接入 - Mid-session push：Claude Code / opencode / pi / Reason 直接 mid-session 收到；Cursor / Gemini / Copilot 只能 next-step - check_inbox 主动：push 受限 harness 用 - Notify pop-up：屏幕弹窗 + system notification，系统级唤起 - macOS menu bar icon：状态显示 - Reason CLI + Reason Cloud：可选账号体系，但纯本地 team 也可用 - From tincan：升级而非迁移，team / agents / background service 自动迁移

风险。 - n0 公司默认 relay 看见加密字节：除非团队自建 relay，否则 n0 仍能见流量元数据（IP / 时长） - Mid-session push 对 harness 入侵深：可能在 harness 升级时频繁不兼容 - 没有 server 听起来很美，但消息存储、发现、team roster 都得本地——distributed consistency 复杂 - Cursor / Gemini / Copilot 只能 next-step：push 受限的 harness 体验仍差 - 201⭐ 早期信号：P2P 网络效应需要 ≥ 5 个互相连通的成员才好用

是否值得跟踪。 值得——这是 2026-Q4 "team coding agents 总线"赛道的代表项目，取代 Slack 在 coding-agent 时代的协作位置 是合理愿景。iroh + MCP + multi-harness 接入 + tincan 升级路径四个要素都齐了。
