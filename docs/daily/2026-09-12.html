今日重点趋势（按排名）

1. LLM 终端侧本地隐私脱敏网关成为独立品类（趋势分 90）

  • xiaYuTian11/maskit（3 天 143⭐ / fork 24 / fork/star 16.8% / AGPL-3.0）——「数据面具」本地隐私脱敏与还原网关。Python 桌面 + Tauri 壳；mitmproxy MITM 改写请求结构化占位符打码；SSE 流式无感还原；100% 本地零遥测；支持 Cursor / Claude Code / Codex / Pi / OpenCode / ChatGPT 以及任意可配 Base URL 的 LLM 工具。Windows / macOS 桌面 + Docker（amd64 / arm64）。仓库 size 3.2 MB，但内含完整桌面壳。
  • 核心价值定位： 当前 LLM Coding Agent 工具普遍把代码原文（含凭据、内网 IP、PII）发到远端——maskit 在中间架一道透明网关，出网前打码、入网时还原。它是 LLM 工具链里"隐私侧"的标准件，类比 SaaS 服务的 zero-trust 网关。
  • AGPL-3.0 与商业 fork 信号： fork/star 16.8% 与昨日 mizzlelover/gongwen-gbt9704-skill（18.6%）同处于"企业级 fork"区间；AGPL-3.0 在企业内网使用完全合规，但禁止修改后闭源分发。
  • 价值判断： 它解决的是"用 LLM 工具又怕泄密"的真实痛点；技术栈（mitmproxy + Tauri + 流式还原）成熟；产品形态（桌面 + Docker + 跨工具）完整。是否能进入"基础设施"取决于是否被 IDE / Coding Agent 工具官方接入或内置。

2. 面向「pro」的 GPU 渲染 IDE 上线（趋势分 86）

  • unstablebuild/rune（2 天 154⭐ / fork 8 / GPL-3.0）——「the development environment for pros」。Go 实现；character-grid 渲染界面（GPU 加速）；编辑器 + 终端 + CLI tools + language intelligence + debugging + AI agents 同窗；cmd/rune 主程序 + cmd/rune-agent 扩展解耦（agent 不污染核心编辑器，扩展系统被推到能承载复杂应用）；docs.rune.build 内嵌文档；仓库 size 147.9 MB（含 WebP 截图 + 文档资源）。
  • 架构亮点： 把「agent 当扩展而不是核心」——与 Cursor / Claude Code / Codex 的"agent 是入口"路线相反，Rune 是"编辑器是入口，agent 是插件"。这是对 「核心编辑器不应被 agent 行为污染」 这一开发者诉求的明确回答。
  • GPL-3.0 与 GitHub Actions 完备： Linux + macOS 双平台 CI + Lint + codecov，6 项 badge 全亮；Discord + Reddit 社区同步运营。
  • 价值判断： 它与 Helix / Lapce / Zed / Onlook 处于同一赛道，但把「pro」做到极致（character-grid + 多 workspace + 扩展系统承载 agent）。能否破圈取决于扩展系统的真实生态丰富度。

重点项目深度分析（top 3）

🏆 xiaYuTian11/maskit（Score 90）

定位判断： LLM 终端侧隐私脱敏网关。它不是单纯的 PII 替换工具，而是把「出网打码 / 入网还原 / 工具通用 / 本地部署」四件事打包成一等公民产品。与昨日 maskit（同作者昨日未上榜）和 mizzlelover/gongwen-gbt9704-skill（Skill 形态）相比，maskit 是中间件形态——不替代 LLM 工具本身，而是在中间架透明网关。

关键技术亮点： 1. mitmproxy MITM 改写——HTTPS 中间人改写请求体，把数据库连接串、内网 IP、手机号、API Key 替换成结构化占位符 2. SSE 流式还原——模型回答流式到达时按占位符表毫秒级还原成原文；用户感知不到脱敏存在 3. 桌面 + Docker 双形态——Tauri 桌面壳（Windows/macOS）+ Docker 镜像（amd64/arm64）；CI 完整 4. 工具通用——任意可配 Base URL 的 LLM 工具都可用（Cursor/Claude Code/Codex/Pi/OpenCode/ChatGPT） 5. 100% 本地零遥测——README 明示无外发统计

风险/局限： - AGPL-3.0 是双刃剑——企业内部可自由用，但任何修改 + 分发都必须开源 - "结构化占位符"对模型的影响未公开 benchmark——可能影响模型对脱敏后代码的理解精度 - 流式还原在双向加密 / 非标 SSE 协议下可能丢失顺序

🏆 unstablebuild/rune（Score 86）

定位判断： 面向 pro 的 GPU 渲染 IDE。它的核心哲学是「core editor 干净，agent 当扩展」——cmd/rune-agent 与 cmd/rune 解耦，agent 不会污染编辑器的正常编程体验。这与 Helix（modal editing）、Lapce（Rust 原生 GPU）、Zed（Rust + GPU + 自研编辑栈）同属 GPU 渲染 IDE 赛道，但把「pro」做到极简：character-grid 界面 + 多 workspace + 内嵌文档 + 完整 CI。

关键技术亮点： 1. GPU 渲染 character-grid 界面——类似 Helix 的 TUI 思路但走 GPU 路径，渲染性能更高 2. cmd/rune + cmd/rune-agent 解耦——主程序不含 agent 逻辑，agent 是独立扩展；扩展系统被设计为「能承载复杂应用」 3. 多 workspace 同窗——编辑器、终端、文件树、agent session 同窗口共存 4. 内嵌 docs——cmd/rune/docs markdown 内嵌二进制，通过 docs:/// workspace 访问 5. 完整 GitHub Actions——Linux / macOS / Lint / codecov 四套 CI，6 项 badge 全亮

风险/局限： - GPL-3.0 与商业 fork 兼容性差——企业内集成需要明确法律意见 - 扩展生态尚未形成——目前看是 solo 项目，没有现成的"扩展市场" - character-grid 界面学习曲线高于 GUI IDE——目标用户明确是「pro」 - 仓库 size 147.9 MB（含截图与文档资源）

🏆 sumimakito/Mac-Duo（Score 84）

定位判断： MacBook iPhone Duo 动效移植工具，2026-09-12 灵感动爆点。Metal GPU 渲染 + ScreenCaptureKit 实时屏幕内容 + 菜单栏控制 = 一键复刻 iOS 26 的 Duo 折叠动画。它不是工具，是「氛围 App」——满足用户的视觉愉悦而非生产效率。

关键技术亮点： 1. Metal + ScreenCaptureKit——GPU 渲染 perspective / blur / dim 配合屏幕实时截屏 2. 菜单栏控制——无需打开主窗口，所有调节在菜单栏 3. 盖角度实时驱动——MacBook 铰链传感器（部分机型）检测盖角度变化 4. prebuilt DMG 已签名 + 公证——Apple Silicon + Intel 双架构 5. Moeru AI 赞助 Apple Developer Program——README 明示商业化路径

风险/局限： - 依赖 macOS 14 + 兼容盖角度传感器的 MacBook——机型覆盖有限 - 屏实时截屏会触发 Screen Recording 权限弹窗——首次启动体验门槛 - "氛围 App" 难以持续维护——iPhone Duo 热度过后活跃度可能骤降

风险与机遇

风险： - maskit 的结构化占位符对模型理解的影响——README 未提供脱敏后代码准确率 benchmark；下游用户需要自己做 A/B 测试 - Rune GPL-3.0 与企业生态兼容性——如果未来扩展系统要求企业级 license 兼容，需要明确商业条款 - Mac-Duo 类 App 的"氛围依赖症"——iPhone Duo 热度一旦消退，整个集群活跃度都会下降 - tracecrate 只读特性能否守住——如果未来用户要求"导出到 SaaS"，产品哲学可能漂移 - opensend 无 license 字段——企业采用前需先补 license 声明 - omarchy-apple-dev 8KB Shell 是否真能在纯 Linux 端独立完成 IPA——物理上不可能，需要明确外部依赖

机遇： - LLM 隐私网关赛道被 maskit 验证——任何做企业 / 政企 / 医疗 LLM 工具集成的团队都可能 fork 这条线 - Omarchy 生态扩展——如果 omarchy-apple-dev 把"无 Xcode iOS 开发"跑通，可以反向推动 Apple 调整 Xcode CLI 边界 - tracecrate 的"local-first observability"哲学——可复用到 OTLP / OpenInference / Phoenix 生态 - AI 视频 Skill 垂直化——reelbench-skills 之后可能陆续出现 "AI 配音 Skill"、"AI 转场 Skill" 等垂直 Skill 包
