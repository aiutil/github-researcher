趋势一（rank 1，score 97）：仓库名成为攻击面 —— fork=false 不等于「与上游无关」

⭐⭐⭐⭐⭐ 本日榜单最高位是 AIRzZ90/study-materials-fork，318⭐ / ⑂465 / subs 3 / 89 commits / 147 blobs / TypeScript / NOASSERTION，而它的三个关键元数据字段全部指向「这看起来像一个正常的独立项目」：

⭐⭐⭐⭐⭐ 本日报在 10-26 记录过一条判据，并已写进 projects/raven.md：「判定改名必须比对 id 与 parent，而不是比对路径或描述。」 ⭐⭐⭐⭐⭐ 本例是对那条判据的一次必要修正：parent=null 只能证明「GitHub 不认为它是 fork」，不能证明「它与上游无关」。 ⭐⭐⭐⭐⭐ 本日报实测的镜像证据是：src/App.tsx（12,133 B）、src-tauri/src/net.rs（32,104 B）、package.json（1,289 B）三个文件在镜像中完整存在且上游侧已不存在；镜像的 89 条 commit 覆盖 2026-11-03T14:16:53Z → 2026-11-12T11:06:32Z，其中含 Merge branch 'Minireel:main' into security-audit（2026-11-08T15:05:14Z）、Merge pull request #43 from Minireel/codex/fix-ios-build（2026-11-10T01:21:16Z）这类直接引用上游 PR 号的提交标题；且上游的 LICENSE 随清空一起消失，而镜像的 LICENSE 里仍保留着上游的 copyright 行。

⭐⭐⭐⭐⭐ 这与 11-08 记录的「判据被针对」是同一手法的镜像版： 11-08 是「README 里写一句『Star the repo if it helped you』→ 同时抬高 stars 与 subs」；本日是「把上游的 star 存量整体搬到自己名下 → 用镜像收割注意力」。⭐⭐⭐⭐⭐ 两者共用一条更一般的规律：任何基于元数据的判据，其失效方向都会被投放方读到。 ⭐⭐⭐⭐⭐ 而本日报同时观察到：这个镜像的 fork 到达时间分布是正常的（抽样 60 个 fork，中位间隔 139 秒，2/59 个 ≤10 秒，跨度 241.7 分钟）—— 即连「fork 时间分布」这条 11-07 立下的判据，在一个「非 fork 的镜像」面前也失效了，因为它本来就不是通过 fork 机制分发的。

⭐⭐⭐⭐ 本日这条趋势的核心结论可写成一句可执行的话： 对任何 fork=false 且 parent=null 的高星仓库，必须额外做一次「上游血缘」检查 —— 取其 LICENSE 中的 copyright 归属、commit 标题中出现的上游 PR/分支引用、以及 pushed_at 早于 created_at 的情况；这三者中任意一项出现，即应判定为「镜像或迁移」，而非「新建项目」。 ⭐⭐⭐⭐⭐ 本日报据此修正了 projects/raven.md 那条 10-26 的判据表述。

最值得关注的方向

⭐⭐⭐⭐⭐ 方向一：把「上游血缘」做成一等判据。 ⭐⭐⭐⭐ 本日 AIRzZ90/study-materials-fork 证明了 fork=false + parent=null 的组合不足以判定「独立项目」。⭐⭐⭐⭐⭐ 本日报建议把以下三项做成自动检查，并加入每日 sweep：（a） LICENSE 中的 copyright 归属是否指向另一个账号；（b） commit 标题中是否出现上游的 PR 号或分支名；（c） pushed_at 是否早于 created_at。⭐⭐⭐⭐⭐ 本日报在本期已把这三项用于 Minireel/HGhub ↔ AIRzZ90/study-materials-fork 这一对，三项全部命中。

⭐⭐⭐⭐ 方向二：README 的第一屏位置比末尾更危险。 ⭐⭐⭐⭐ 本日的载荷在 ## Installation 的第一段（11-08 的 ⭐ Star the repo 在末尾，11-11 的投递在 ## 🚀 Quick Start 首屏）。⭐⭐⭐⭐⭐ 三个样本的位置都不同，恰好说明「按位置过滤载荷」这类规则不成立 —— 规则必须针对「指令型语义」，而不是「出现的位置」。

⭐⭐⭐⭐⭐ 方向三：账号注册时间窗是比 star 值更耐用的判据。 ⭐⭐⭐⭐ 本日三批投放体给出了三个账号注册窗口：载荷族是 2026-06-26 的 3 分 28 秒，rpocket 族是 2026-11-06/07 的 2 小时，而本日真项目的 owner 账号创建时间跨度是 2009–2025 年（simonklee 2009、egoist 2014、lawandrorder 2015、bea4dev 2017、rivet-dev 2019）。⭐⭐⭐⭐⭐ 账号年龄与注册密度这两项，在本日全部三批投放体上都成立，且不受 star 值分布变化的影响。

Top 1 · AIRzZ90/study-materials-fork — 把「点 star」写成镜像的准入条件
