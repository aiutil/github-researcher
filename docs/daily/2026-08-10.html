3. phone-harness——"phone-as-tool" agent 终端赛道出现（评分 84）

ShawnPana/phone-harness（789⭐ / 60 fork / 1 subscriber，Python，MIT，创建 08-07）核心技术（README 可核验）：

  • 传输层：macOS iPhone Mirroring 窗口——iPhone Mirroring（macOS Sequoia+）把 iPhone 渲染为 Mac 窗口，转发鼠标/键盘输入为触摸。这给 agent 提供了完整的"看+操作"通道，无需越狱、无需 Xcode、无需 WebDriverAgent。
  • 眼睛：screencapture + Vision 框架 OCR——只截取 Mirroring 窗口，用 Apple Vision 框架 OCR 识别所有可见文本及其坐标。README 称之为"the poor man's DOM"。
  • 手：HID 级 CGEvents——在 HID tap 层投递事件：tap、长按、拖拽/滑动、滚动手势、unicode 输入、app 快捷键（Cmd+1 Home、Cmd+2 App Switcher、Cmd+3 Spotlight）。
  • 验证：再截图——"No DOM means the capture is the ground truth"（README 原文）。
  • 架构：SKILL.md（agent 面向的产品面）+ install.md（权限引导）+ src/phone_harness/（约 500 行保护核心：mirror.py / ocr.py / helpers.py / admin.py / run.py）+ agent-workspace/agent_helpers.py（agent 编辑的 helper，自动加载）。传输无状态（无 daemon），每次调用自包含。

架构启发： 这是继 browser-harness（agent 控制浏览器）、computer-use（agent 控制桌面）之后，"agent 控制物理设备"赛道的延伸。核心思想是用 OS 级的"无障碍/镜像"能力替代专用自动化框架——iPhone Mirroring 提供了"把手机变成 Mac 窗口"的官方通道，agent 不需要专门的移动端自动化（如 Appium/WDA），只需要"截图+OCR+点击"这个最原始的 GUI 自动化循环。README 明确列出了"踩坑"：AppleScript click at 被忽略（窗口是视频流，无 accessibility tree）、unicode key payload 无效（Mirroring 转发 HID keycodes）、慢速 touch-drag 几乎不动 iOS 列表（要用 wheel scroll）。这些是真实的工程经验。

局限（README 自述 + 观察）： 仅 macOS（iPhone Mirroring 是 macOS Sequoia+ 功能）；单机单会话；无多点触控（无 pinch）、无相机/Face ID 流程、DRM 视频渲染为黑色；OCR 看文本不看语义（无标签图标需截图+vision 模型）。subscribers 仅 1，极早期。
