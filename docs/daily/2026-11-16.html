最值得关注的方向

⭐⭐⭐⭐⭐ 方向一：镜像检测从「上游是否清空」转向「blob sha 是否相同」。 11-13 记录的 AIRzZ90/study-materials-fork 之所以难判，是因为上游被作者亲手清空了历史，镜像方是被迫的；⭐⭐⭐⭐⭐ 本日的 Gemini-Config-Checker- 族不同 —— 上游 MatinSenPai/Gemini-Config-Checker 完好无损（72 blobs、144⭐、MIT、2026-10-03 创建），镜像方在 11-15 主动选择复制 21 份、改许可、换载荷。⭐⭐⭐⭐⭐ 检测法也随之变得便宜：不需要下载任何内容，只要把同族仓库 git/trees 的 blob sha 与上游逐一比对即可。

⭐⭐⭐⭐⭐ 方向二：同一账号矩阵可以同时承载多个家族，这是比「命名词根」更硬的判据。 Gemini-Config-Checker- / GitHub-Copilot-app / ai--manus2.0 三个家族名毫无词法关系，⭐⭐⭐⭐⭐ 但它们共用同一批账号、共用同一个「每家族 9–10 个副本 + 1 个主仓库 + 1 个随机名占位 = 恰好 12」的结构。⭐⭐⭐⭐⭐ 这提示：追踪投放体时，应当把「账号 → 仓库列表」作为一等公民，而不是把仓库名当作主要线索。

⭐⭐⭐⭐⭐ 方向三：「发布历史」需要降级为「可核验的发布证据」。 本日两个样本（21 个镜像复刻 53 条 commit 消息；1 个 commit 后 7 秒内发 4 个语义无关的 release）说明：⭐⭐⭐⭐⭐ commit 数、release 数、版本号这三个字段都可以脱离代码演进独立存在。⭐⭐⭐⭐⭐ 真正有信息量的是「tag 指向的 commit 是否不同」「release 资产是否随版本变化」「代码是否在版本之间发生过实质改动」。

⭐⭐⭐⭐⭐ 方向四：诚实边界的三种落点已经形成模式。 AGENTS.md 的「不做什么」清单（pydtcpip）、pre-commit 可读的 token 预算（coordinator）、README 的签名校验条款（interspace）—— ⭐⭐⭐⭐⭐ 三者都是把纪律做进机器能读到的地方，而不是写进散文。
